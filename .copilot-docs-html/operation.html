運用・操作フロー

ユーザが orchestrator を中心に開発タスクを進めるときの操作ガイド。追加指示や再計画の戻り方も含めて現在の流れを示す。

この資料で分かること

  • 開発タスク依頼の手順
  • 追加指示、再計画、HTML ドキュメント生成までの流れ

関連資料

  • agents.md — エージェントの役割と使用ツール
  • ui-design.md — UI 変更時の共通方針

前提条件

  • .copilot-mcp/ がビルド済みであること
  • VS Code の MCP 設定が完了していること
  • 複数フォルダワークスペースでは、.copilot フォルダが共有制御ルートとして開かれていること

開発タスクの依頼

目的

コード実装・修正を orchestrator に依頼し、必要な再計画を含めて完了まで進める。

手順

  1. Copilot Chat で orchestrator を呼び出す。
  2. 実装したい内容、制約、避けたいことを自然言語で伝える。
  3. orchestrator がタスク種別を判定し、必要に応じて interviewer や investigator を呼び出す。
  4. planner が plan を提示したら、ok か、修正指示か、追加指示か、追加指示ファイルの有無かを返す。
  5. ok の場合、developer、tester、reviewer が順に進む。
  6. reviewer が ng を返した場合、orchestrator は preferences.md を維持したまま planner に戻す。
  7. reviewer が ok を返した場合、全サブタスクの結果を集約して documenter が .copilot-docs/ を更新し、.copilot-docs-html/ を再生成する。
  8. 最終結果に対して追加指示があれば、orchestrator が interviewer を使って整理し、最初の分類からやり直す。

結果

  • .copilot-work/[task-id]/ に hearing、preferences、調査、plan、開発結果、テスト結果、レビューが残る
  • .copilot-docs/ が更新される
  • .copilot-docs-html/ が再生成され、一覧検索とページ内検索で閲覧できる

追加指示の返し方

返し方 使う場面 orchestrator の動作
ok 現在の plan / 結果で進めてよい 次の工程へ進む、または終了する
ng（修正） 現在の案に問題がある interviewer で修正意図を整理し、preferences.md を更新して再計画する
追加指示 新しい条件を足したい 追加内容を hearing と preferences に反映して最初から流し直す
追加指示ファイルがある 要件を別ファイルで渡したい ファイルパスを interviewer に渡して読み込ませ、以後の plan に反映する
Interviewer で整理する 指示を会話しながら固めたい interviewer を呼び、十分な情報が集まるまで質問を続ける

ファイルリンク表示

orchestrator は plan 承認の確認時などに、関連ファイルへのマークダウンリンクをチャット上に表示する。ユーザはリンクをクリックしてファイル内容を直接確認できる。

表示されるリンク例:

  • [plan1.md](.copilot-work/{task-id}/plans/plan1.md)
  • [hearing.md](.copilot-work/{task-id}/hearing.md)
  • [investigation.md](.copilot-work/{task-id}/investigation.md)

セットアップタスク

目的

プロジェクトの初期ドキュメントや運用資料を整備する。

手順

  1. orchestrator にセットアップ内容を依頼する。
  2. investigator が現状を調査する。
  3. planner がドキュメント更新計画を作成する。
  4. documenter が .copilot-docs/ を更新し、.copilot-docs-html/ を再生成する。

結果

  • 共有制御ルート配下の .copilot-docs/ と .copilot-docs-html/ が最新化される
