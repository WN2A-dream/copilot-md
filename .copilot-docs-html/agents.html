AI エージェント一覧と開発フロー

agents/ 配下のエージェント定義と instructions/ 配下の指示書の詳細を説明する。

この資料で分かること

  • 各エージェントの責務、入出力、呼び出しタイミング
  • 指示書の適用対象と優先順位
  • エージェント間の依存関係とデータの流れ

関連資料

  • architecture.md — 全体構成とデータフロー
  • api.md — MCP ツール仕様
  • operation.md — ユーザ操作フロー

エージェント概要

エージェント 役割 ユーザ呼び出し
orchestrator タスク管理、サブエージェント呼び出し、再計画ループ 可
splitter タスク規模判定、コンテキスト分割 不可
interviewer ユーザヒアリング、要件明確化 不可
investigator コードベース調査、情報収集 不可
planner 実装計画作成 不可
developer コード実装 不可
tester テスト実行・修正 不可
reviewer コードレビュー 不可
documenter ドキュメント更新、HTML 生成 不可

エージェント詳細

orchestrator

タスクの受付からサブエージェントの呼び出し、完了判定までを管理する。

項目 内容
定義ファイル agents/orchestrator.agent.md
使用ツール askQuestions, agent, todo
入力 ユーザからのタスク依頼
出力 サブエージェント呼び出し、最終結果報告
モード setup, design, investigation, development

呼び出しタイミング

  • ユーザが Copilot Chat でタスクを依頼したとき

splitter

タスクがコンテキストサイズに収まるかを判定し、必要に応じて分割する。

項目 内容
定義ファイル agents/splitter.agent.md
使用ツール read, search, file_info, json_read, yaml_read
入力 タスク内容、コードベース情報
出力 分割判定結果、サブタスク一覧

呼び出しタイミング

  • orchestrator がタスク規模を判定するとき

interviewer

ユーザから要件を聞き出し、明確化する。ヒアリング結果と継続的な嗜好を記録する。

項目 内容
定義ファイル agents/interviewer.agent.md
使用ツール askQuestions, read, search, copilot_work_write
入力 ユーザ応答、既存の preferences.md
出力 .copilot-work/[task-id]/hearing.md, .copilot-work/[task-id]/preferences.md
モード development, design

呼び出しタイミング

  • 要件が不明確でヒアリングが必要なとき
  • ユーザが追加指示を整理したいとき
  • 継続的な嗜好の記録が必要なとき

investigator

コードベースを調査し、実装に必要な情報を収集する。

項目 内容
定義ファイル agents/investigator.agent.md
使用ツール read, search, file_info, git_status, git_log, git_show, git_diff, copilot_work_write, json_read, xml_read, yaml_read, toml_read, ini_read
入力 タスク内容、コードベース
出力 .copilot-work/[task-id]/investigation.md

呼び出しタイミング

  • 実装計画の前に現状把握が必要なとき
  • 調査のみのタスクを実行するとき

planner

調査結果に基づいて実装計画を作成する。レビュー ng 時は再計画を行う。

項目 内容
定義ファイル agents/planner.agent.md
使用ツール read, search, copilot_work_write, json_read, xml_read, yaml_read, toml_read, ini_read
入力 investigation.md, hearing.md, preferences.md, review.md（再計画時）
出力 .copilot-work/[task-id]/plans/plan[n].md

呼び出しタイミング

  • investigator の調査完了後
  • reviewer が ng を返したとき（再計画）

developer

計画に基づいてコードを実装する。

項目 内容
定義ファイル agents/developer.agent.md
使用ツール read, edit, search, copilot_work_write, json_read, json_write, json_get, json_set, xml_read, xml_write, yaml_read, yaml_write, toml_read, toml_write, ini_read, ini_write
入力 plans/plan[n].md, preferences.md
出力 実装ファイル, .copilot-work/[task-id]/devs/dev[n].md

呼び出しタイミング

  • ユーザが plan に ok を返したとき

tester

テストを実行し、失敗時は修正を行う。

項目 内容
定義ファイル agents/tester.agent.md
使用ツール read, edit, search, copilot_work_write, maven_, gradle_, java_, dotnet_, json_read, json_write, xml_read, xml_write, yaml_read, yaml_write
入力 実装ファイル, テストコード
出力 .copilot-work/[task-id]/test-report.md
対応フレームワーク Maven, Gradle, Java（ビルドツールなし）, dotnet

呼び出しタイミング

  • developer の実装完了後

reviewer

コードレビューを行い、問題があれば再計画を要求する。

項目 内容
定義ファイル agents/reviewer.agent.md
使用ツール read, search, copilot_work_write, json_read, xml_read, yaml_read, toml_read, ini_read
入力 devs/dev[n].md, test-report.md, preferences.md
出力 .copilot-work/[task-id]/review.md

呼び出しタイミング

  • tester のテスト完了後（または developer の実装完了後）

documenter

ドキュメントを更新し、HTML 版を生成する。

項目 内容
定義ファイル agents/documenter.agent.md
使用ツール read, search, copilot_docs_write, md2html, git_status, git_diff, git_log, json_read, yaml_read, toml_read
入力 開発結果ファイル群、既存の .copilot-docs/
出力 .copilot-docs/ 更新, .copilot-docs-html/ 再生成

呼び出しタイミング

  • 全サブタスクの reviewer が ok を返した後（1回のみ）

指示書一覧

ファイル 適用対象 概要
default.instructions.md **/* プロジェクト全体のルールとフロー定義
mcp.instructions.md エージェント全般 local-command MCP ツール利用ガイド
copilot-docs.instructions.md .copilot-docs/**/*.md ドキュメント構成ルール（AI 最適化）
markdown.instructions.md **/*.md markdownlint ルール抜粋

指示書の優先順位

  1. ファイル固有の指示（applyTo でマッチ）
  2. プロジェクト全体の指示（default.instructions.md）
  3. エージェント定義内の指示

各指示書の詳細

default.instructions.md

プロジェクト全体に適用される基本ルール。

  • ドキュメント・コメント・コミットメッセージは日本語
  • .copilot-docs/ と .copilot-work/ は共有制御ルートに集約
  • UI タスクでは ui-design.md を優先参照

mcp.instructions.md

local-command MCP サーバーのツール利用ルール。

  • 全ツールに共通する workingDirectory パラメータの指定方法
  • カテゴリ別のツール一覧と使用エージェント
  • レスポンス形式とエラーハンドリング

copilot-docs.instructions.md

.copilot-docs/ 配下のドキュメント構成ルール。

  • 結論 → 判断材料 → 詳細の順で記述
  • 各ファイル冒頭に3行以内の要約を配置
  • 「この資料で分かること」「関連資料」を要約直後に配置

markdown.instructions.md

Markdown ファイル全般に適用される記法ルール。

  • markdownlint のルール抜粋
  • 見出しレベルの適切な設定

共有制御ルート

複数フォルダワークスペースでは、agents/、instructions/、.copilot-docs/、.copilot-work/ を持つフォルダを共有制御ルートとして扱う。

  • .copilot-work/ と .copilot-docs/ の読み書きは常にこのルートに集約する
  • .copilot-docs-html/ も同じルートに生成する
  • 実装対象のコード探索は他ワークスペースフォルダへ広げてよい

管理ファイルの流れ

生成者 出力先 主な消費者
interviewer .copilot-work/[task-id]/hearing.md planner, documenter
interviewer .copilot-work/[task-id]/preferences.md planner, developer, reviewer, documenter
investigator .copilot-work/[task-id]/investigation.md planner
planner .copilot-work/[task-id]/plans/plan[n].md developer
developer .copilot-work/[task-id]/devs/dev[n].md reviewer
tester .copilot-work/[task-id]/test-report.md reviewer
reviewer .copilot-work/[task-id]/review.md planner
documenter .copilot-docs/, .copilot-docs-html/ ユーザ

好み・方向性の保持

ユーザの計画修正や追加指示で継続的な嗜好が判明した場合、orchestrator は interviewer を通して .copilot-work/[task-id]/preferences.md を更新する。

  • planner は再計画時も preferences.md を前提条件として読む
  • developer と reviewer は実装・評価の両方で同じ方向性を維持する
  • 繰り返し現れるルールは instructions / skills への昇格候補として扱う

開発フロー

通常の開発フローは次のループで進む。

flowchart TD
    A[タスク受付] --> B{タスク種別判定}
    B -->|setup| C[investigator → planner → documenter]
    B -->|design| D[interviewer → planner]
    B -->|investigation| E[investigator のみ]
    B -->|development| F[investigator]

    F --> G[planner]
    G --> H{plan 確認}
    H -->|ok| I[developer]
    H -->|ng/追加指示| G
    I --> J[tester]
    J --> K[reviewer]
    K -->|ok| L[documenter]
    K -->|ng| G
    L --> M[完了]

設計・調査・セットアップフロー

種別 概要
設計 interviewer が詳細ヒアリングを行い、その結果をそのまま実装または文書化に接続する
調査 investigator の結果をもとに、実装へ進むか文書化だけで終えるかを選ぶ
セットアップ investigator → planner → documenter の順でドキュメント整備を行い、HTML 版も再生成する
