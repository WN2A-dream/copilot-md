共有制御ルート

複数フォルダワークスペースでは、agents/、instructions/、.copilot-docs/、.copilot-work/ を持つフォルダを共有制御ルートとして扱う。

  • .copilot-work/ と .copilot-docs/ の読み書きは常にこのルートに集約する
  • .copilot-docs-html/ も同じルートに生成する
  • 実装対象のコード探索は他ワークスペースフォルダへ広げてよい

好み・方向性の保持

ユーザの計画修正や追加指示で継続的な嗜好が判明した場合、orchestrator は interviewer を通して .copilot-work/[task-id]/preferences.md を更新する。

  • planner は再計画時も preferences.md を前提条件として読む
  • developer と reviewer は実装・評価の両方で同じ方向性を維持する
  • 繰り返し現れるルールは instructions / skills への昇格候補として扱う

開発フロー

通常の開発フローは次のループで進む。

1. orchestrator が共有制御ルートとタスク種別を確定する
2. 必要に応じて splitter でタスクを分割する
3. investigator が調査結果を作る
4. planner が plan を作る
5. ユーザが plan に対して ok / ng / 追加指示 / 追加指示ファイル / interviewer 整理 を選ぶ
6. ok なら developer → tester → reviewer を進める
7. reviewer が ng を返した場合は plan 作成に戻る
8. reviewer が ok を返したら documenter が `.copilot-docs/` を更新し、`md2html` で `.copilot-docs-html/` を再生成する
9. 最終結果に対してユーザが ok を返すまで、orchestrator が追加指示を整理して 1 に戻る

設計・調査・セットアップフロー

種別 概要
設計 interviewer が詳細ヒアリングを行い、その結果をそのまま実装または文書化に接続する
