エージェント概要

エージェント 役割 ユーザ呼び出し
orchestrator タスク管理、サブエージェント呼び出し、統一フロー制御 可
splitter タスク規模判定、コンテキスト分割 不可

reviewer コードレビュー（観点別分割対応） 不可

エージェント詳細

orchestrator

タスクの受付からサブエージェントの呼び出し、完了判定までを管理する。.copilot-docs/ のドキュメントと .copilot-work/{task-id}/ 内の管理ファイルを参照してタスク分類・分割の精度を高める。

項目 内容
定義ファイル agents/orchestrator.agent.md
使用ツール askQuestions, agent, todo, copilot_docs_read, copilot_work_read
入力 ユーザからのタスク依頼
出力 サブエージェント呼び出し、最終結果報告
フロー構造 check_shortcut + run_unified_flow の2層構造

統一フロー

4モード分岐（setup/design/investigation/development）を廃止し、以下の統一フローで処理する。

  1. auto_mode 判定 — ユーザ入力からキーワード検出で自動実行モードを判定
  2. ショートカット判定 — design-only / investigation-only を検出、該当しなければ統一フローへ
  3. 統一フロー — splitter → investigator → planner → developer → tester + reviewer（並列） → documenter

ユーザ確認ゲート

orchestrator は各フェーズにユーザ確認ゲート（G1〜G6）を配置し、auto_mode 時はゲートをスキップする。テスト失敗・レビュー NG 時は auto_mode でも investigator に自動リトライし、MAX_RETRY 超過で自動停止する。

レビューのサイズ判定

変更ファイル数が REVIEW_SPLIT_THRESHOLD（10）を超える場合、3つのスキルファイルを使って reviewer を3回並列呼び出しし、aggregate_reviews で統合する。

呼び出しタイミング

  • ユーザが Copilot Chat でタスクを依頼したとき

splitter

タスクがコンテキストサイズに収まるかを判定し、必要に応じて分割する。

項目 内容
定義ファイル agents/splitter.agent.md
使用ツール read, search, file_info, json_read, yaml_read
入力 タスク内容、コードベース情報
出力 分割判定結果、サブタスク一覧

呼び出しタイミング

  • orchestrator が統一フローの最初でタスク規模を判定するとき

interviewer

ユーザから要件を聞き出し、明確化する。ヒアリング結果と継続的な嗜好を記録する。

項目 内容
定義ファイル agents/interviewer.agent.md
使用ツール askQuestions, read, search, copilot_work_write, copilot_work_read
入力 ユーザ応答、既存の preferences.md
出力 .copilot-work/[task-id]/hearing.md, .copilot-work/[task-id]/preferences.md

呼び出しタイミング

  • design-only ショートカットでの設計ヒアリング（非 auto_mode）
  • 手戻り時の情報補完
  • ユーザが追加指示を整理したいとき

investigator

コードベースを調査し、実装に必要な情報を収集する。

項目 内容
定義ファイル agents/investigator.agent.md
使用ツール read, search, file_info, git_status, git_log, git_show, git_diff, copilot_work_write, copilot_docs_read, copilot_work_read, json_read, xml_read, yaml_read, toml_read, ini_read
入力 タスク内容、コードベース
出力 .copilot-work/[task-id]/investigation.md

呼び出しタイミング

  • 統一フローで splitter の後に実行
  • テスト失敗・レビュー NG 時のリトライ

planner

調査結果に基づいて実装計画を作成する。レビュー ng 時は再計画を行う。

項目 内容
定義ファイル agents/planner.agent.md
使用ツール read, search, copilot_work_write, copilot_docs_read, copilot_work_read, json_read, xml_read, yaml_read, toml_read, ini_read
入力 investigation.md, hearing.md, preferences.md, review.md（再計画時）
出力 .copilot-work/[task-id]/plans/plan[n].md

呼び出しタイミング

  • investigator の調査完了後
  • reviewer が ng を返したとき（再計画）

developer

計画に基づいてコードを実装する。

項目 内容
定義ファイル agents/developer.agent.md
使用ツール read, edit, search, copilot_work_write, copilot_docs_read, copilot_work_read, json_read, json_write, json_get, json_set, xml_read, xml_write, yaml_read, yaml_write, toml_read, toml_write, ini_read, ini_write, window_*
入力 plans/plan[n].md, preferences.md
出力 実装ファイル, .copilot-work/[task-id]/devs/dev[n].md

呼び出しタイミング

  • planner の計画承認後（auto_mode 時は自動進行）

tester

テストを実行し、失敗時は修正を行う。BuildResult 構造化レスポンスの errors、testSummary、rawOutput を活用して効率的にビルド→修正ループを回す。

項目 内容
定義ファイル agents/tester.agent.md
使用ツール read, edit, search, copilot_work_write, copilot_work_read, maven_, gradle_, java_, dotnet_, npm_, maven_dependencies, gradle_dependencies, dotnet_dependencies, npm_dependencies, json_read, json_write, xml_read, xml_write, yaml_read, yaml_write, window_
入力 実装ファイル, テストコード
出力 .copilot-work/[task-id]/test-report.md
対応フレームワーク Maven, Gradle, Java（ビルドツールなし）, dotnet, Node.js (npm)

呼び出しタイミング

  • developer の実装完了後（reviewer と並列実行）

reviewer

コードレビューを行い、問題があれば再計画を要求する。skill_filepath パラメータにより観点別レビューに対応する。

項目 内容
定義ファイル agents/reviewer.agent.md
使用ツール read, search, copilot_work_write, copilot_docs_read, copilot_work_read, json_read, xml_read, yaml_read, toml_read, ini_read
入力 devs/dev[n].md, test-report.md, preferences.md, スキルファイル（観点別時）
出力 .copilot-work/[task-id]/review.md（全観点）または review-{aspect}.md（観点別）
返り値 status（ok/ng）, issues（指摘事項リスト）

観点別レビュー

skill_filepath が指定された場合、該当スキルのカテゴリのみレビューし、出力先を review-{aspect_name}.md に分離する。未指定時は従来どおり全カテゴリをレビューし review.md に出力する。

レビュー観点

カテゴリ 内容
正確性 要件整合、ロジック正確性
セキュリティ OWASP Top 10
保守性 拡張性、構造的整合性
可読性 命名規則、コメント、一貫性

呼び出しタイミング

  • developer の実装完了後（tester と並列実行）
  • 観点別分割時は orchestrator が3回並列呼び出し

documenter

ドキュメントを更新し、HTML 版を生成する。

項目 内容
定義ファイル agents/documenter.agent.md
使用ツール read, search, copilot_docs_read, copilot_docs_write, copilot_work_read, md2html, git_status, git_diff, git_log, json_read, yaml_read, toml_read
入力 開発結果ファイル群、既存の .copilot-docs/
出力 .copilot-docs/ 更新, .copilot-docs-html/ 再生成

呼び出しタイミング

  • 全サブタスクの reviewer が ok を返した後（分割判定付きで1回呼び出し）

スキル定義

skills/ 配下にレビュー観点別のスキルファイルを配置する。reviewer が skill_filepath で参照し、レビュー対象カテゴリを絞り込む。

ファイル 観点 内容
skills/review-correctness.md 正確性 正確性・要件整合・セキュリティ（OWASP Top 10）
skills/review-maintainability.md 保守性 保守性・拡張性
skills/review-readability.md 可読性 可読性・一貫性

指示書一覧

ファイル 適用対象 概要
default.instructions.md **/* プロジェクト全体のルールとフロー定義
mcp.instructions.md エージェント全般 local-command MCP ツール利用ガイド
copilot-docs.instructions.md .copilot-docs/**/*.md ドキュメント構成ルール（AI 最適化）
markdown.instructions.md **/*.md markdownlint ルール抜粋

指示書の優先順位

  1. ファイル固有の指示（applyTo でマッチ）
  2. プロジェクト全体の指示（default.instructions.md）
  3. エージェント定義内の指示

各指示書の詳細

default.instructions.md

プロジェクト全体に適用される基本ルール。

  • ドキュメント・コメント・コミットメッセージは日本語
  • .copilot-docs/ と .copilot-work/ は共有制御ルートに集約
  • UI タスクでは ui-design.md を優先参照

mcp.instructions.md

local-command MCP サーバーのツール利用ルール。

  • 全ツールに共通する workingDirectory パラメータの指定方法
  • カテゴリ別のツール一覧と使用エージェント
  • レスポンス形式（汎用テキスト / 構造化 BuildResult）とエラーハンドリング

copilot-docs.instructions.md

.copilot-docs/ 配下のドキュメント構成ルール。

  • 結論 → 判断材料 → 詳細の順で記述
  • 各ファイル冒頭に3行以内の要約を配置
  • 「この資料で分かること」「関連資料」を要約直後に配置

markdown.instructions.md

Markdown ファイル全般に適用される記法ルール。

  • markdownlint のルール抜粋
  • 見出しレベルの適切な設定

共有制御ルート

複数フォルダワークスペースでは、agents/、instructions/、.copilot-docs/、.copilot-work/ を持つフォルダを共有制御ルートとして扱う。

  • .copilot-work/ と .copilot-docs/ の読み書きは常にこのルートに集約する
  • .copilot-docs-html/ も同じルートに生成する
  • 実装対象のコード探索は他ワークスペースフォルダへ広げてよい

管理ファイルの流れ

生成者 出力先 主な消費者
interviewer .copilot-work/[task-id]/hearing.md planner, documenter
interviewer .copilot-work/[task-id]/preferences.md planner, developer, reviewer, documenter
investigator .copilot-work/[task-id]/investigation.md planner
planner .copilot-work/[task-id]/plans/plan[n].md developer
developer .copilot-work/[task-id]/devs/dev[n].md reviewer
tester .copilot-work/[task-id]/test-report.md orchestrator（判定用）
reviewer .copilot-work/[task-id]/review.md orchestrator → investigator（手戻り時）
reviewer .copilot-work/[task-id]/review-{aspect}.md orchestrator（aggregate_reviews で統合）
documenter .copilot-docs/, .copilot-docs-html/ ユーザ

好み・方向性の保持

ユーザの計画修正や追加指示で継続的な嗜好が判明した場合、orchestrator は interviewer を通して .copilot-work/[task-id]/preferences.md を更新する。

  • planner は再計画時も preferences.md を前提条件として読む
  • developer と reviewer は実装・評価の両方で同じ方向性を維持する
  • 繰り返し現れるルールは instructions / skills への昇格候補として扱う

開発フロー

統一フローは次の流れで進む。ショートカット（design-only / investigation-only）に該当しない限り、全タスクがこのフローを通る。

flowchart TD
    A[タスク受付] --> AA{auto_mode 判定}
    AA --> B{ショートカット判定}
    B -->|design-only| D[interviewer → planner]
    B -->|investigation-only| E[investigator のみ]
    B -->|該当なし| F[splitter → investigator]

    F --> G[planner]
    G --> H{plan 確認}
    H -->|ok / auto| I[developer]
    H -->|ng/追加指示| G
    I --> J[tester + reviewer 並列]
    J -->|ok| K{ユーザ確認}
    J -->|ng| L[investigator リトライ]
    L --> G
    K -->|ok / auto| M[documenter]
    M --> N[完了]

セットアップタスクは統一フロー内で正規化され、developer/reviewer スキップの特別扱いは廃止された。
