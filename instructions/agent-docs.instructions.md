# .agent-docs の構成ルール

## 目的

- `.agent-docs` は、AI エージェントが短時間で全体像と参照先を掴むための一次資料として扱う
- `operation.md` はユーザも読む前提で、視認性と操作しやすさを優先する

## 記述ルール

- 結論は冒頭に、判断材料や詳細は後ろに書く
- ファイルを細かく分割して、1 ファイルあたりの論点を絞ることで、必要以上のコンテキストを消費しないようにする

## 参照ルール

- まずは `index.md` を参照して、全体像と目的のドキュメントを把握する
- 目的に応じて、必要なドキュメントを選んで参照する
- ドキュメント内の参照は、必要な情報が得られる最も近い場所を指すようにする

## 推奨ファイル構成

- `.agent-docs/`：プロジェクトドキュメント
  - `index.md`：プロジェクト全体の概要とドキュメント構成の案内
  - `design.md`：設計
  - `view.md`：UI・UX構成
  - `class.md`：クラス構成
  - `api.md`：API仕様
  - `operation.md`：利用時操作フロー
  - その他、詳細な説明をトピックごとに
  などのファイルに分けて整理
- `.agent-work/`：タスク処理のための一時的なドキュメント
  - `[task_id]/`：タスクごとのサブディレクトリ
    - `hearing{n}.md`：interviewerエージェントがユーザからのヒアリング内容を記録するファイル
    - `feedback.md`：orchestratorがハーネスのフィードバックを提供するファイル。以下の場合に
      - タスクに必要な権限やツールが不足していた場合にその内容
      - ユーザの指示から傾向や好みが読み取れた場合にその内容
      - コマンド等の試行が成功した場合に成功した手順

## 更新方針

- 文書更新時は、変更箇所だけでなく、参照先との整合性も確認する
- 仕様変更があった場合は、`index.md` から辿れる状態を維持する
- 古い説明を残すより、不要になった記述を削除して文書を短く保つ
